# code-data 模板:伪数据/代码联动页

概念的关键是「数据怎么排、怎么对齐、怎么流动」,而不是「形长什么样」——顶点属性与索引、结构体/内存布局、字节编码、协议字段、SQL/正则/状态机的执行过程、调用栈。这类概念用一小段**具体伪数据**加几行**代码**表达,比任何图示都准;进一步做成**数据-代码联动的执行动画**,读者看着一行代码跑下去、数据格里哪几格被读、哪格被写。先读 `../SKILL.md` 的 tokens、交付模式与「表达形式选择」。

## 构建前:实例与剧本

- **最小具体实例**:3 个顶点,不是 1 万个;4 个字节,不是 4MB。小到一屏放得下、能手算验证——读者能心算核对每一步,信任感就是这么来的。
- **核心困惑**:这个概念最容易想歪的点是什么(如"索引到底怎么取数")?整个联动设计围绕攻破它。
- **执行剧本**:把概念写成 3~8 行伪代码或真实代码,每行对应一步;再列出每一步的读集(读了哪些格子)与写集(写了哪格)。剧本先于页面存在。

## 页面结构

沿用 graphic 的版式规则(每节一屏、布局自由、eyebrow 标签、深链)。六段:

1. **动机**——一个具体反常现象,不用术语(如:改了 uv 数组第一个元素,三角形却没变化)
2. **数据登场**——伪数据表全景,各数组/结构用 c-* 颜色编码,先混个眼熟
3. **联动拆解**——主交互屏:**代码在左,数据状态在右**(分栏硬规则同 graphic);步进执行,当前行、读集、写集实时高亮
4. **误解证伪**——把最常见的错误直觉做成一步当场跑(如"position 取 0 号、uv 取 1 号"执行给你看会得到什么),证伪比正面重复有效
5. **真实世界的回响**——指回真实 API / 字段名 / buffer(`gl.vertexAttribPointer`、VAO、实际显存布局)
6. **小结 + 挑战**——三行收束,留一个要读者心算一步的挑战

## 组件模式

- **数据表**:`font-mono` 数字、列对齐;表头(数组名/下标)`text-muted`;1px `border-hairline` 分隔。**每个数组/数据结构分配一个 c-* 色**(教学强调色沿用 graphic 模板),贯穿表头、代码里的对应 token、连线与高亮——同一对象同色,规则不变。
- **代码窗**:code-window 配方(`bg-dark text-on-dark font-mono rounded-lg p-6`);当前执行行 `bg-dark-elevated` 高亮 + 左侧 3px `bg-primary` 竖条;行号 `text-muted-soft`。
- **读集高亮**:被读取的数据格 2px `ring` 用该数组的 c-* 色。
- **写集高亮**:被写入的格子 `color-mix(in srgb, var(--color-c-*) 25%, transparent)` 填充,一闪后定格。
- **连线**:代码 token → 数据格,SVG overlay 曲线,颜色跟随该数据结构的 c-* 色;当前步显示,过后淡出——线是把"这行代码碰了哪些数据"画出来的唯一手段,别省。
- **步进控制**:同 graphic(「上一步 / 下一步」+ `n / N` 读数 + 播放/暂停);键盘左右方向键可用。
- **大读数**:每步的派生结论(如"取出的顶点 = (-50, -50, 0)")用 `font-mono text-3xl` 大读数卡,不做成小字标签。

## 联动执行动画规则

- **一步 = 代码一行**,状态变化全部落在数据表上,没有看不见的中间态。
- 三种联动高亮必须同时在场且颜色可分:当前行(primary 系)、读集(c-* ring)、写集(c-* 填充)。
- **反向链接**:hover 任一数据格,显示"它是哪一步/哪行写入的"——读者经常想倒着追。
- 播放 = 自动步进,可暂停可 scrub;`prefers-reduced-motion` 命中时默认暂停,手动步进保留。
- 剧本允许分支(如 if 命不命中):默认值走最有教学性的那支,另一支做成「亲手验证」里的开关。

## 色彩语义

- 每个数据结构一个 c-* 色,全程一致;coral(`c-coral`)稀缺,只给主角机制(本例:index 数组那一行)。
- 当前执行行用 primary 系高亮,与数据结构的 c-* 色不混淆——一个是"执行到哪",一个是"数据是谁"。
